# dt 1차 버전 설계

작성일: 2026-11-04

## 1. 무엇이고 왜 만드는가

dt는 실내 3D 모델 위에 카메라와 센서를 배치하고, 외부 시스템이 보내는 이벤트를 3D 위치, 알람, 통계로 보여주는 웹 기반 3D 관제 도구다.

기존 관제 화면은 이벤트를 목록이나 2D 지도로 보여준다. 그래서 여러 층 건물에서는 이벤트가 "어디서" 났는지 바로 알기 어렵다. dt는 이벤트를 건물 3D 모델의 해당 층·위치에 띄워서 이 문제를 줄인다.

사용자는 정해져 있지 않다. 회사 동료, 다른 개발자, 그 밖에 필요한 누구든 될 수 있다. 공개 레포로 배포하므로 **처음 보는 사람이 레포를 받아 바로 실행해볼 수 있어야 한다.**

## 2. 성공 기준

아래 흐름이 처음부터 끝까지 동작하면 1차 버전은 성공이다.

1. `docker compose up`으로 실행하고 관리자로 로그인한다.
2. 현장을 만들고 3D 모델 파일(GLB)을 올리면 3D 화면이 뜬다.
3. 층의 높이 구간을 지정한다.
4. 원하는 위치에 카메라를 놓고 방향과 화각을 조정한다.
5. 연동 키를 발급받는다.
6. 공개된 HTTP 인터페이스로 이벤트를 보낸다.
7. 알람 패널에 알람이 뜨고, 3D의 해당 위치에 표시되며, 확인 처리할 수 있다.
8. 대시보드에 통계가 반영된다.

자기 모델이 없어도 레포에 든 **샘플 모델과 이벤트 시뮬레이터**만으로 위 흐름 전체를 재현할 수 있어야 한다. 이 흐름은 자동 E2E 테스트로도 검증한다.

## 3. 목표, 비목표, 반목표

### 목표

- 위 성공 기준 전체
- 외부 시스템이 문서만 보고 연동할 수 있는 연동 인터페이스(이벤트·위치 창구)와 규격 문서
- 온프레미스(폐쇄망 포함)와 클라우드 모두 배포 설정만으로 동작

### 비목표 (1차에 하지 않음)

- 3D 모델 제작. 모델은 외부에서 받는다.
- 카메라 영상으로 위치 계산하기 (캘리브레이션, 픽셀 좌표를 3D로 변환, 여러 카메라에 찍힌 같은 객체 합치기)
- 이력 재생, 카메라 영상 팝업, 녹화 재생, 시점 북마크
- 알람의 조치·종료 단계, 담당자 지정, 알람음 설정
- 역할별 권한, 여러 사용자 계정
- 트윈 화면에서 실제 장치 제어, 시뮬레이션
- 장치 온라인/오프라인 상태 수신
- 서버 여러 대로 수평 확장
- 모바일 화면 최적화

### 반목표 (동작하더라도 실패로 보는 것)

- 레포 어디든(코드, 주석, 문서, 커밋 메시지, 브랜치 이름, 샘플 데이터) **특정 회사의 내부 제품명·시스템명**, 사내 주소, 고객 정보, 실제 건물 도면이 들어가는 것. dt는 어느 회사에도 종속되지 않은 범용 도구로 보여야 한다.
- 처음 보는 사람이 README만 보고 실행하지 못하는 것
- 실행 중에 외부 인터넷(CDN, 웹폰트, 디코더 다운로드 등)이 필요해서 폐쇄망에서 화면이 안 뜨는 것
- 같은 상황에서 메시지가 반복해서 들어올 때 알람 목록이 폭주해서 관제 요원이 쓸 수 없게 되는 것 (설계자 판단으로 추가)

## 4. 제약

- **공개 레포:** 비밀값을 커밋하지 않는다. 설정은 환경변수와 `.env.example`로 안내한다.
- **배포 환경:** 온프레미스와 클라우드를 모두 지원한다. 차이는 저장소와 DB 연결 설정뿐이다.
- **폐쇄망:** 브라우저와 서버 모두 실행 중에 외부 네트워크를 호출하지 않는다. Draco/Meshopt 디코더, 폰트, 라이브러리를 모두 번들에 포함하거나 직접 호스팅한다.
- **언어:**
  - 화면은 영어가 기본이고 한국어로 전환할 수 있다.
  - README는 영어와 한국어를 모두 둔다. 나머지 문서는 한국어로 쓴다.
  - 코드, 식별자, 커밋 메시지는 영어로 쓴다.
- **관제 PC 사양:** 내장 그래픽 노트북에서 샘플 모델이 부드럽게 돌아가야 한다. 목표는 30fps 이상이다(설계자 판단).

## 5. 사용자가 정한 것

### 5.1 공간 구조

- 현장을 여러 개 등록할 수 있다.
- 현장마다 3D 모델 하나를 올린다. 모델 안에 층이 여러 개 있다.
- 3D 모델은 외부에서 받는다. 받는 형식은 규격 문서로 정한다. 포맷은 glTF 2.0 바이너리(GLB), 단위는 m이고, 높이 축과 원점, 폴리곤·텍스처 권장 상한을 명시한다.

### 5.2 장치

- 장치 유형은 **카메라**와 **일반 센서** 두 가지로 시작한다.
  - 카메라는 3D에 화각(시야 범위)을 표시한다.
  - 센서는 아이콘으로 표시한다.
- 장치는 3D 모델 위 고정 위치에 등록한다. 장치가 놓인 층이 그 장치에서 온 메시지의 층이 된다(높이 처리는 5.3).

### 5.3 연동 인터페이스

외부 시스템은 HTTP로 메시지를 보낸다. **받는 창구는 두 개다.**

- **이벤트 창구:** 알람을 만들고 대시보드 통계에 들어간다. 예: 침입 감지, 화재 감지.
- **위치 창구:** 3D의 객체 마커만 움직인다. 알람을 만들지 않고 통계에도 들어가지 않는다. 예: 출입 태그가 사람 위치를 1초마다 보내는 경우.

알람과 위치가 같이 필요하면(침입한 사람의 위치 등) 이벤트에 좌표와 객체 정보를 담아 보낸다.

두 창구 모두 연동 키를 HTTP 헤더로 받는다(설계자 판단).

**이벤트 메시지 필드**

| 필드 | 필수 | 설명 |
|---|---|---|
| 장치 ID | O | dt에 등록된 장치의 ID. 층을 정하는 기준이다. |
| 이벤트 유형 | O | 문자열. 알람과 대시보드 분류에 쓴다. |
| 발생 시각 | O | 시간대를 포함한 ISO 8601 형식 |
| 심각도 | X | dt가 정한 레벨 중 하나 |
| 수평 좌표 (x, y) | X | 모델 좌표계 기준, 단위 m |
| 객체 ID | X | 외부 시스템이 붙인 객체 식별자 |
| 객체 유형 | X | `person`, `vehicle`, `object` |
| 이벤트 ID | X | 재전송 중복 제거용 (6.8) |

**위치 메시지 필드**

| 필드 | 필수 | 설명 |
|---|---|---|
| 장치 ID | O | 층을 정하는 기준 |
| 수평 좌표 (x, y) | O | 위치 메시지는 좌표가 핵심이라 필수다. |
| 측정 시각 | O | ISO 8601 |
| 객체 ID | X | 없으면 회색 점 |
| 객체 유형 | X | 이벤트 메시지와 같은 값 |

규칙:

- **ID 충돌 방지:** 연동 키를 외부 시스템마다 발급하고, 서버가 키로 출처를 붙인다. 외부 시스템끼리 ID 체계를 맞출 필요가 없다.
- **높이와 층:** 높이 좌표는 받지 않는다. 장치 ID로 등록된 장치의 층을 쓴다. 사용자 의도는 "고정된 장치 주변이니 층은 정해진다"이다. 그래서 좌표가 있는 객체와 이벤트는 장치의 설치 높이(천장 등)가 아니라 **그 층의 바닥면 위**에 놓는다. 바닥면 높이는 해당 (x, y)에서 층 구간 안을 아래로 레이캐스트해서 찾고, 못 찾으면 층 구간의 시작 높이를 쓴다.
- **좌표가 없을 때 (이벤트만 해당):** 장치 자체의 위치에 표시한다.
- **객체 ID:** 있으면 ID마다 다른 색상과 라벨로 표시한다. 없으면 회색으로 표시한다.
- **객체 유형:** 사람·차량·사물 모형으로 표시한다.
- **사라지는 규칙:** 같은 객체의 정보(위치 메시지든, 객체가 담긴 이벤트 메시지든)가 더 오지 않으면 3초 동안 투명해지며 사라진다. 그래서 규격 문서에 "추적 중인 객체는 최소 1초에 한 번 위치를 전송"을 명시한다.
- **심각도:**
  - 값이 있으면 dt가 정한 레벨로 받는다.
  - 값이 없으면 연동 키별 기본값을 쓴다. 기본값의 초기값은 최고 레벨이고, 관리자가 바꿀 수 있다.
  - 정한 레벨 밖의 값이 오면 400으로 거부한다.
- **축 정의:** 규격 문서에 축 정의를 명시한다.

### 5.4 화면

- **메인 모니터링 화면 (A안):**
  - 상단에 핵심 숫자 세 개
  - 가운데에 3D를 크게
  - 오른쪽에 알람 패널. 알람마다 확인 버튼이 있다.
  - 상단 메뉴: 현장 선택, 모니터링 / 대시보드 / 설정 탭, 미확인 알람 수 배지
- **층 표시:** 선택한 층은 불투명하게, 나머지 층은 반투명하게 그린다.
- **이벤트 마커:** 항상 맨 위에 그려서 어느 층에 있든 가려지지 않게 한다.
- **대시보드:** 별도 탭으로 둔다.

### 5.5 대시보드 통계

모든 항목에 기간 필터를 적용한다.

- 기간별 이벤트 수 추이 (시간·일 단위)
- 이벤트 유형별, 심각도별 비율
- 장치별, 층별 이벤트 순위
- 현재 확인 안 된 알람 수

### 5.6 운영

- **로그인:** 관리자 계정 하나로 시작한다. 초기 비밀번호는 환경변수로 받는다.
- **연동 키:** 관리자가 설정 화면에서 발급하고 폐기한다.

### 5.7 배포

- `docker compose up` 한 번으로 앱과 DB가 같이 뜬다.
- **파일 저장:** 기본은 로컬 디스크다. 설정으로 S3 호환 저장소(MinIO, GCS, AWS S3)로 바꿀 수 있다.

## 6. 설계자가 정한 것

사용자는 아래 항목을 설계자에게 맡겼다. 사용자가 검토할 수 있도록 이유와 함께 적는다.

### 6.1 기술 스택

| 영역 | 선택 | 이유 |
|---|---|---|
| 언어 | TypeScript (화면·서버 공통) | 이벤트 규격을 화면과 서버가 같은 정의로 공유한다. |
| 화면 | React + Vite + react-three-fiber + drei | 3D 부품(배치 핸들, 카메라 이동, HTML 라벨, 인스턴싱)이 가장 많이 준비된 생태계 |
| 화면 상태 | zustand | 3D 씬과 패널 사이 상태 공유에 가볍게 쓸 수 있다. |
| 서버 | Node.js + Fastify | 가볍고 빠르며, 스키마 기반 검증과 OpenAPI 생성 플러그인이 있다. |
| 스키마 | zod (공유 패키지) | 한 번 정의해서 입력 검증, 화면 타입, OpenAPI 문서를 모두 만든다. |
| DB | PostgreSQL + Drizzle ORM | 통계 집계 쿼리에 강하고, 온프레미스·클라우드 모두 흔하다. |
| 실시간 | WebSocket | 이벤트와 객체 위치를 화면에 바로 전달한다. |
| 3D 파일 처리 | @gltf-transform, gltf-validator | 업로드할 때 형식 검사, 자동 압축, 층 높이 제안 |
| 파일 저장 | 로컬 디스크 / S3 호환 (AWS SDK v3) | 같은 인터페이스 뒤에 두 가지 구현 |
| 테스트 | Vitest (단위), Playwright (E2E) | 성공 기준 흐름 전체를 브라우저로 자동 검증 |
| 배포 | Docker 이미지 하나(화면 정적 파일 + API) + PostgreSQL | 단일 서버, 메시지 큐·캐시 서버 없음 |

레포는 pnpm 워크스페이스 모노레포로 구성한다.

- `apps/web`: 화면
- `apps/server`: API 서버
- `packages/shared`: 스키마, 타입
- `tools/simulator`: 이벤트 시뮬레이터
- `tools/sample-model`: 샘플 모델 생성기
- `docs/`: 규격 문서 등

### 6.2 층 지정 방식: 높이 구간

- 층은 이름 규칙이 아니라 **높이 구간**으로 정의한다. 예: 1F는 0~4m, 2F는 4~8m.
  - 모델이 통짜 메시 하나여도 층 구분이 된다.
  - 받은 모델이 층 노드 이름 규칙을 지키지 않아도 쓸 수 있다.
- 업로드할 때 서버가 수평면(바닥 슬래브)의 높이 분포로 층 높이를 제안한다. 관리자가 화면에서 고친다.
- 렌더링은 클리핑 평면으로 층을 나눈다. 선택한 층 구간은 불투명하게, 나머지 구간은 반투명하게 그린다.

### 6.3 좌표계

- **모델 좌표계:** glTF 표준(Y축이 위, 단위 m)을 그대로 쓴다.
- **API 좌표:** 평면도 기준 `x`, `y`로 받는다. 모델 좌표 (X, Z)와의 대응은 `x = X`, `y = -Z`다. 위에서 내려다볼 때 x는 오른쪽, y는 위쪽이다.
- **좌표 확인 도구:** 3D에서 마우스를 올리면 해당 지점의 평면 좌표를 화면에 보여준다. 연동하는 사람이 보낼 좌표를 쉽게 찾게 하기 위해서다.

### 6.4 장치 ID

- 관리자가 장치를 등록할 때 직접 정한다. **dt 전체에서 유일해야 한다.**
  - 그래서 메시지에 현장 필드가 없어도 장치 ID만으로 현장과 층이 정해진다.
  - 연동 키 하나로 여러 현장의 장치에 메시지를 보낼 수 있다.
- 외부 시스템은 이 ID로 메시지를 보낸다. 등록되지 않은 장치 ID가 오면 거부한다(404).

### 6.5 알람 묶기

반목표인 "알람 폭주"를 막기 위한 규칙이다. 이벤트 창구에만 적용된다.

- 하나의 이벤트 메시지는 하나의 **이벤트 기록**이 된다.
- 알람은 이벤트 기록을 묶은 단위다. 같은 상황이 이어지는 동안은 알람 하나로 본다.
  - **같은 상황인지 판단:** 연동 키, 장치 ID, 이벤트 유형, 객체 ID가 모두 같으면 같은 상황이다. 객체 ID가 없으면 앞의 세 개만 본다.
  - **이어지는지 판단:** 같은 상황의 메시지가 이전 메시지로부터 10초 안에 오면 이어지는 것으로 본다. 10초 넘게 끊겼다가 다시 오면 새 알람이다.
  - **합칠 때 갱신하는 것:** 발생 횟수, 마지막 시각, 심각도(더 높은 쪽).
- 확인한 알람에도 이어지는 메시지가 오면 같은 알람에 조용히 합친다. 확인 상태는 그대로 유지한다. 그래서 확인 버튼을 누르자마자 같은 알람이 다시 뜨지 않는다.
- 3D의 객체 마커는 알람 묶기와 별개로 메시지마다 위치를 갱신한다.
- 대시보드의 "이벤트 수"는 알람 기준으로 센다. 이벤트 메시지 원본은 저장만 한다.

### 6.6 알람 상태

- 상태는 **미확인 → 확인** 두 단계다. 확인할 때 확인 시각을 저장하고, 메모는 선택으로 받는다.
- 알람 패널에서 알람을 클릭하면 해당 층으로 전환하고 위치로 시점이 이동한다.
- 미확인 알람의 위치에는 3D에 빨간 맥박 링을 표시한다. 링은 확인하면 사라지고, 3초 페이드 규칙의 대상이 아니다.

### 6.7 심각도 레벨

- `critical`, `major`, `minor`, `info` 네 단계다.
- 연동 키 기본값의 초기값은 `critical`이다.

### 6.8 이벤트 ID (선택 필드 추가)

- 이벤트 메시지에 **이벤트 ID**를 선택 필드로 추가했다(5.3 표).
- 같은 연동 키에서 같은 이벤트 ID가 다시 오면 무시하고 성공으로 응답한다. 외부 시스템이 네트워크 오류로 재전송해도 중복이 생기지 않는다.
- 위치 메시지는 최신 값으로 덮어쓰기만 하므로 이벤트 ID가 필요 없다.

### 6.9 시각

- 발생 시각과 dt가 받은 시각을 둘 다 저장한다.
- 통계는 발생 시각 기준이다. 3초 페이드는 받은 시각 기준이다.

### 6.10 상단 핵심 숫자

- 세 개로 둔다: **미확인 알람 수**, **오늘 이벤트 수**, **지금 3D에 보이는 객체 수**
- 장치 온라인 상태는 비목표라서 목업의 "온라인 장치" 대신 "보이는 객체 수"를 쓴다.

### 6.11 객체 모형

- 사람, 차량, 사물 모형은 코드에서 단순한 도형으로 만든다: 사람은 캡슐, 차량은 낮은 상자, 사물은 정육면체.
- 객체 유형이 없으면 기본 구 모양으로 표시한다.
- 색상은 객체 ID 해시로 정해진 팔레트에서 고르고, 객체 ID가 없으면 회색이다.

### 6.12 샘플과 도구

- **샘플 모델:** 3층 사무실 모델을 코드로 생성한다. 라이선스 문제가 없고, 납품 규격의 예시 역할도 한다.
- **이벤트 시뮬레이터:** CLI로 만든다. 연동 키와 장치 목록을 받아서 아래를 보낸다.
  - 위치 창구: 움직이는 객체 (ID 있음), ID 없는 탐지
  - 이벤트 창구: 좌표와 객체가 담긴 침입 이벤트, 좌표 없는 센서 이벤트
- **동작 확인 스크립트:** 샘플 현장 설정(모델, 층, 장치)을 한 번에 만드는 시드 스크립트를 둔다. 수동 흐름(성공 기준 2~5)과 별개로, 바로 데모를 볼 수 있게 하기 위해서다.

### 6.13 실시간 전달

- **이벤트:** 서버가 받아서 DB에 저장한 뒤 화면에 WebSocket으로 보낸다.
- **위치:** DB에 저장하지 않는다. 서버 메모리에 객체별 최신 위치만 TTL로 보관한다. 이력 재생이 비목표라 저장할 이유가 없고, 메시지 양이 가장 많은 부분이라 저장하지 않으면 부담이 크게 준다. 단일 서버라 Redis는 필요 없다.
- **위치 전송 묶기:** 화면에 보낼 위치 갱신은 약 200ms마다 묶어서 보낸다.
- **현장별 구독:**
  - 화면은 보고 있는 현장의 이벤트·위치를 모두 받는다.
  - 모든 현장의 알람 요약(현장별 미확인 수, 새 알람)도 받는다.
- **새로 접속한 화면:** 현재 보이는 객체와 미확인 알람 목록을 먼저 받는다.

### 6.14 다른 현장의 알람

- 상단 배지는 **모든 현장**의 미확인 알람 수를 보여준다.
- 알람 패널과 상단 핵심 숫자는 보고 있는 현장 기준이다.
- 다른 현장에서 `critical`·`major` 알람이 생기면 현장 이름이 담긴 토스트를 띄운다. 토스트를 누르면 그 현장으로 이동한다.

### 6.15 처리 규모 목표

1차 버전은 서버 한 대에서 다음 규모를 목표로 한다. 성능 테스트도 이 기준으로 한다.

- 현장 10개, 현장당 장치 200개
- 한 현장에 동시에 보이는 객체 300개 (내장 그래픽에서 30fps 유지)
- 위치 메시지 전체 초당 500건, 이벤트 메시지 전체 초당 20건

위치 창구는 메시지를 여러 개 묶은 배열도 받는다. 많은 객체를 추적하는 시스템이 요청 수를 줄일 수 있게 하기 위해서다.
