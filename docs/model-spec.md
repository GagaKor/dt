# 3D 모델 규격

dt는 현장마다 3D 모델 하나를 받는다. 이 문서는 모델을 만들어 납품하는 쪽이 지켜야 할 규격을 정한다. 샘플은 `samples/office-3f.glb`(3층 사무실, 코드로 생성)이고 `tools/sample-model`에서 다시 만들 수 있다.

## 1. 형식과 좌표

| 항목 | 규격 |
|---|---|
| 형식 | glTF 2.0 바이너리(`.glb`). 분리된 `.gltf` + 리소스는 받지 않는다 |
| 단위 | 미터(m). 1 단위 = 1 m |
| 높이 축 | **Y-up** (glTF 표준) |
| 평면 | X-Z 평면이 바닥이다 |
| 원점 | 건물 평면에서 의미 있는 기준점(예: 1층 바닥의 한쪽 모서리)에 둔다. 1층 바닥면은 Y = 0 근처가 되도록 한다 |

API 좌표와의 대응은 `x = 모델 X`, `y = -모델 Z`다([연동 가이드](integration.md#4-좌표계)). 위에서 내려다볼 때 모델 +X가 오른쪽, 모델 -Z가 위쪽(북)이다. 건물의 북쪽이 모델 -Z를 향하도록 만들면 평면도와 화면이 일치한다.

## 2. 층 정의

층은 노드 이름 규칙이 아니라 **높이 구간**으로 정한다. 예: 1F는 0 ~ 4 m, 2F는 4 ~ 8 m.

- 모델이 통짜 메시 하나여도 층이 구분된다. 층 이름 규칙을 지키지 않아도 된다.
- 업로드하면 서버가 위를 향한 수평면(바닥 슬래브)의 높이 분포를 보고 **층 높이를 자동 제안**한다. 설정 > 현장 상세에서 제안을 적용하거나 직접 고친 뒤 저장한다.
- 층 구간은 겹치지 않아야 하고, 장치가 놓인 층은 삭제할 수 없다.
- 화면은 선택한 층을 불투명하게, 나머지를 반투명하게 그린다. 선택한 층의 불투명 구간은 `[층 시작 높이 - 0.05 m, 층 끝 높이 - 0.5 m]`이다. 위층 슬래브(천장)를 잘라서 위에서 층 내부가 보이게 하기 위해서다.
- 객체와 이벤트는 해당 층의 바닥면 위에 놓인다. 바닥면은 아래로 쏜 레이가 `[층 시작 높이 - 0.05 m, 층 시작 높이 + 0.5 m]` 구간에서 처음 맞는 면이다(계단·단차를 0.5 m까지 허용). 이 구간에 면이 없으면 층 시작 높이를 쓴다. 그래서 **바닥이 모델에 실제 면으로 있어야** 하고, 바닥보다 0.5 m 넘게 높은 책상이나 선반 윗면은 바닥으로 잡히지 않는다.

자동 제안을 잘 받으려면 각 층 바닥이 위를 향한 면(법선이 거의 +Y)으로 모델링돼 있어야 한다.

## 3. 권장 상한

| 항목 | 권장 |
|---|---|
| 삼각형 수 | 150만 개 이하 |
| 텍스처 | 한 변 2048 px 이하 |
| 파일 크기 | `MAX_MODEL_MB` 이하(기본 500 MB). 넘으면 `413 model_too_large` |

상한은 권장값이다. 넘어도 읽히지만 내장 그래픽이나 저사양 PC에서 프레임이 떨어질 수 있다. 실내 모니터링에는 가구 같은 작은 사물보다 벽, 바닥, 기둥 중심의 가벼운 모델이 낫다.

## 4. 업로드 때 일어나는 일

서버는 업로드한 GLB를 검사하고 다시 인코딩해서 저장한다.

1. glTF 검증기로 형식을 검사한다. GLB가 아니면 `422 not_glb`, glTF가 깨졌거나 보이는 형상이 없으면 `422 invalid_gltf`다.
2. 압축 확장 중 Draco(`KHR_draco_mesh_compression`)와 Meshopt(`EXT_meshopt_compression`)로 압축된 입력은 **받는다**.
3. 중복 데이터 제거(dedup), 정점 병합(weld)을 하고 **Meshopt로 다시 압축**해서 저장한다. 화면은 이 결과를 번들에 포함된 디코더로 읽는다(외부 네트워크 호출 없음).
4. 층 높이 제안과 단위 경고를 계산해 응답에 담는다.

### 받는 것과 거부하는 것

| 구분 | 확장 |
|---|---|
| 받는다 | `KHR_draco_mesh_compression`, `EXT_meshopt_compression`, `KHR_texture_transform`, `EXT_texture_webp`, 그 밖의 일반 확장(재질·조명 등) |
| 거부한다 | `KHR_texture_basisu`(KTX2/Basis)를 비롯해 `KHR_texture_*`, `EXT_texture_*` 형태의 GPU 압축 텍스처 확장 (위에서 받는 두 개 제외) |

거부하면 `422 unsupported_extension`이고 `details`에 걸린 확장 이름이 담긴다. KTX2/Basis는 브라우저에서 별도 wasm 디코더가 필요해서 받지 않는다. 텍스처를 PNG, JPEG, WebP로 다시 내보낸다.

## 5. 단위 경고

업로드 응답의 경고 목록으로 모델 크기가 이상한지 알려 준다. 업로드는 성공하고, 화면이 경고를 보여 준다.

| 경고 | 조건 | 흔한 원인 |
|---|---|---|
| `units_suspect_too_large` | 모델 전체 높이가 300 m 초과 | mm 또는 cm 단위로 내보냈다 |
| `units_suspect_too_small` | 모델 전체 높이가 1.5 m 미만 | 인치나 km 단위, 또는 축척이 잘못됐다 |

경고가 뜨면 모델을 m 단위로 다시 내보낸다. 단위를 못 맞추면 층 높이 구간과 좌표가 의미 없어진다.

## 6. CAD와 모델링 도구에서 내보낼 때

- **Z-up 도구**(대부분의 CAD, BIM, 3ds Max, Blender의 일부 설정): glTF 내보내기에서 **Y-up 변환**을 켠다. Blender는 `+Y Up` 옵션이 기본으로 켜져 있다. 변환이 안 되면 건물이 옆으로 누워 보이고 층 제안이 틀린다.
- **단위**: 도구의 장면 단위를 m로 맞춘 뒤 내보낸다. mm 도면은 0.001 배율이 필요하다.
- **원점**: 건물에서 멀리 떨어진 좌표(예: 지리 좌표계)를 쓰지 않는다. 수천 m 떨어진 원점은 정밀도 문제를 일으킨다. 건물 근처로 옮긴다.
- **방향**: 내보낸 뒤 평면도의 북쪽이 -Z를 향하는지 확인한다. 반대로 되어 있으면 y 좌표 부호가 헷갈린다.
- **바닥 슬래브**: 층마다 위를 향한 면으로 둔다. 바닥이 없고 벽만 있는 모델은 객체가 층 시작 높이에 놓인다.
- **텍스처**: PNG, JPEG, WebP만 쓴다. KTX2는 쓰지 않는다.
- **불필요한 것**: 숨긴 레이어, 가구 내부, 배관처럼 모니터링에 필요 없는 상세는 빼서 크기를 줄인다.

## 7. 납품 체크리스트

- [ ] `.glb` 한 파일이다.
- [ ] 단위가 m이고 Y-up이다.
- [ ] 건물 높이가 1.5 m ~ 300 m 사이다(경고 없음).
- [ ] 삼각형 150만 개 이하, 텍스처 2048 px 이하다.
- [ ] 텍스처에 KTX2/Basis를 쓰지 않았다.
- [ ] 층마다 바닥 슬래브가 있고, 층 높이 표(예: 1F 0 ~ 4 m)를 함께 전달했다.
